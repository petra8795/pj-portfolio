03 — How I work

Design first, then build it to feel it

Every project starts with research and Figma. Once I know where I'm heading, I build a working prototype in a separate demo environment, so everyone can see how it really behaves, not just how it looks. That's the way I like to work, not a rule: some projects stay in Figma from first idea to handoff.

  1. 01

    Research Design

    I start with user needs, competitor analysis and the business goals behind the request. Understanding the problem comes before drawing anything.

  2. 02

    Explore Design

    Working in Figma with Claude, I can explore far more directions in the same time. Then I narrow them down until one fits the product's style and what it needs to do.

  3. 03

    Prototype Code

    I turn the chosen direction into a working prototype in a dedicated demo environment, with AI writing the code while I make the design decisions. Real motion, timing and data show problems a static mockup hides.

  4. 04

    Share Design Code

    One prototype, many uses: developers see exactly how it should look and behave, sales can show clients what's new, and stakeholders can follow progress. Ideally developers reuse its components, so nothing gets built twice.
