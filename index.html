03 — About me

Petra Jakljevič

Product designer · design engineer

I design for the moments that happen fast: a live match on a phone screen, a bet that's one goal from landing, a halftime break that lasts fifteen minutes. At Sportradar I work on the visual side of live sports, from animated 2.5D and 3D match views to the betting features that sit on top of them.

What makes my work a bit different is that I don't stop at the mockup. I design in Figma, then build the design in the product's real codebase, so I can judge motion, timing and readability against the live thing instead of a static frame. Most of my decisions come from watching the first version fail in the browser and fixing it there.

Before Sportradar I spent four years on health tech, SaaS and brand work: a companion app that made lab results readable for non-scientists, system emails for a CX team, and a brand and website for a design agency. Outside work I build small games, because game feel is the best teacher of interaction design I know.

04 — How I work

Designing with AI as my pair

I use AI every day, mostly Claude Code inside VS Code. It doesn't replace the design thinking, it removes the gap between a design and a working version of it. Vibe coding is how I explore; a clear spec and real verification is how I ship.

  1. 01

    Plan Design

    I write the brief and a short spec first: what it should do, what it must never break. Every AI session reads it before touching code.

  2. 02

    Approve Design

    The AI proposes a plan, I review it like a design critique, and only then does anything get built. No surprise changes.

  3. 03

    Build Code

    Changes land in the product's own codebase, in small chunks. Every visual value is a live slider, so I tune feel in the running app, not in a mockup.

  4. 04

    Verify Code

    I check every change in the running product before it's committed: screenshots at fixed camera angles, scripted checks, and my own eyes. Commits stay human.
